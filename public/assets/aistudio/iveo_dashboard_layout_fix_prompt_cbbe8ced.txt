0. ROLE AND GOAL
---------------------------------------------------------------------
You are a senior product designer + front-end engineer. Redesign the
layout and information architecture of the iveo dashboard
(iveo.site/dashboard) so it looks clean, professional, consistent and
easy to use, especially on mobile (primary use case, ~360-430px wide).

DO NOT remove any working feature. The job is to:
  1. Remove duplicated features / duplicated entry points.
  2. Put every feature in exactly ONE logical home.
  3. Fix spacing, alignment, hierarchy and overlapping UI.
  4. Make the whole dashboard feel like one consistent product.

Keep all existing data, URLs, routes, API calls and behaviour. Only
restructure and restyle the UI unless a requirement below says
otherwise.

Dashboard tabs today: Links | Appearance | Contacts | Analytics |
Settings. (Contacts and Analytics screens were not provided - apply
the global rules in section 2 to them as well and keep their content.)

2. GLOBAL DESIGN REQUIREMENTS (APPLY TO EVERY SCREEN)
---------------------------------------------------------------------

2.1 Design system / tokens (define once, reuse everywhere)
  - Spacing scale: 4 / 8 / 12 / 16 / 24 / 32 px. Page side padding
    16px on mobile, 24px tablet, max content width 720px centered on
    desktop.
  - Cards: white, 1px border #E5E7EB, radius 16px, padding 16-20px,
    16px gap between cards. No nested cards inside cards deeper than
    one level - use dividers (1px, #EEF0F2) for rows inside a card.
  - Typography: ONE font family. Page title 20-22px/600, card title
    16px/600, body 14px/400, helper text 12-13px/400 muted #6B7280.
    No more than 3 font sizes per card.
  - Buttons (3 types only):
      Primary  - solid dark, white text, 44px min height
      Secondary - white with 1px border, 44px min height
      Destructive - red text/border (solid red only inside confirm
      dialogs)
      Text link - for low-priority actions
    All tap targets >= 44x44px.
  - Toggles: visible OFF state (grey track #D1D5DB, white knob) and ON
    state (dark/brand track). Never faint or invisible.
  - Badges: one component. "PRO" = small pill, same style everywhere.
  - Icons: one icon set, 20px, 1.5px stroke, vertically centered with
    the label. Info icons must be INLINE, right after the title, never
    floating at a card corner.
  - Colors: neutral greys + one brand accent. Green only for success
    ("Connected"), red only for destructive/errors.
  - Dark-mode ready: use CSS variables for every color.

2.2 Layout rules
  - Nothing may overlap anything else at any width from 320px up.
  - Reserve bottom padding equal to the height of any fixed/floating
    element so the last item is always reachable.
  - No horizontal scrolling of the page body. No clipped text. Long
    URLs/emails truncate with ellipsis in one line and are fully
    visible on tap/long-press or in the edit view.
  - Each page has: Page title + one-line description -> content cards
    -> (optional) sticky action bar. No blank trailing space.
  - Consistent empty states (icon, one-line message, one primary
    button) and loading skeletons for every list/card.

2.3 Save behaviour (consistent everywhere)
  - Each section that edits fields has its own "Save" button INSIDE
    that card, bottom-right, disabled until something changes.
  - After save: toast "Saved" + button returns to disabled. Show inline
    errors under the field, not only toasts.
  - If the user leaves with unsaved changes, show a confirm dialog.

2.4 Accessibility
  - Contrast >= 4.5:1 for text. Visible focus ring. All icon buttons
    have aria-labels. Touch-friendly; no hover-only actions.

4.3 Social icons card
