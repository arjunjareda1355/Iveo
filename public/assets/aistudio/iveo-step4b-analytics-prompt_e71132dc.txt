3. HOW PRIVACY WORKS (SO YOU CAN EXPLAIN IT TO YOUR USERS)
- No cookies, no visitor IDs and no tracking of individual people. iveo stores only daily COUNTS (for example "12 views from Instagram on mobile on Oct 21"), never a list of visits.
- iveo does not store IP addresses or full referrer addresses in its analytics data. Referrers are grouped into a fixed list of sources (Google, Instagram, and so on) on the visitor's device before anything is sent.
- Visitors who send a Do Not Track or Global Privacy Control signal are not counted. The page owner's own visits are not counted. Obvious bots are not counted.
- No "unique visitors" number is shown, because counting uniques would need a visitor ID. Views mean page loads.
- Be accurate in public: your hosting and database providers still receive each request like any website does and may keep their own technical logs. Say "iveo doesn't store IP addresses, cookies or visitor IDs in its analytics data", not "we collect nothing".
- Please add a short paragraph to your Privacy page before launch. A starting point (not legal advice; have it reviewed for your country):
    "iveo counts page views and link clicks on public pages to show page owners simple statistics. This data is stored as daily totals grouped by source and device type. It does not include cookies, visitor identifiers or IP addresses, and it is not used to track individual people. Visitors who send a Do Not Track or Global Privacy Control signal are not counted."

6. KNOWN LIMITS OF 4B (PLAN FOR THEM)
- Counts are indicative, not audited. Anyone technical could send fake events for a public page; the database bounds how much damage that does (it only inflates numbers).
- Page loads, not people: no unique visitors. No country or city data (that would need a server-side step).
- In-app browsers (Instagram, TikTok) often hide where a visit came from. Use the tracked links (?src=...) for accurate sources.
- Days follow UTC time, so a day's boundary may not match your local midnight.
- Clicks on social icons are not tracked (only links and embeds).
- Long-press "open in new tab" menus and copied links cannot be counted as clicks.
- If you delete a link, its past clicks stay in your totals and show as "Deleted link" in Top links.
- Daily totals are kept indefinitely (they are tiny). Pruning old data is a later chore.

-- 1. DAILY COUNTS TABLE --------------------------------------------------
-- One row per person, day, event type, link, source and device, holding a
-- counter. No visitor identifiers, no IP addresses, no raw referrers.
-- link_id uses an all-zero id for page views (which have no link).
create table if not exists public.analytics_daily (
  user_id text not null references public.profiles (user_id) on delete cascade,
  day date not null,
  event text not null,
  link_id uuid not null default '00000000-0000-0000-0000-000000000000',
  source text not null default '',
  device text not null default 'other',
  hits bigint not null default 0,
  constraint analytics_daily_pkey primary key (user_id, day, event, link_id, source, device),
  constraint analytics_event_valid check (event in ('view', 'click')),
  constraint analytics_device_valid check (device in ('mobile', 'tablet', 'desktop', 'other')),
  constraint analytics_source_valid check (source in (
    '', 'qr', 'google', 'bing', 'duckduckgo', 'instagram', 'facebook', 'x', 'tiktok',
    'youtube', 'linkedin', 'pinterest', 'reddit', 'whatsapp', 'telegram', 'snapchat',
    'threads', 'github', 'discord', 'email', 'other'
  )),
  constraint analytics_link_by_event check (
       (event = 'view'  and link_id = '00000000-0000-0000-0000-000000000000')
    or (event = 'click' and link_id <> '00000000-0000-0000-0000-000000000000')
  ),
  constraint analytics_hits_nonneg check (hits >= 0)
);

-- Nobody can read or write this table directly. Only the two functions
-- below can touch it.
alter table public.analytics_daily enable row level security;
revoke all on public.analytics_daily from anon, authenticated;

-- 2. RECORD AN EVENT (called by visitors; returns nothing; never errors on bad input) ----
create or replace function public.record_page_event(
  p_username text,
  p_event text,
  p_link_id uuid default null,
  p_source text default '',
  p_device text default 'other'
)
returns void
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_user_id text;
  v_source text := coalesce(p_source, '');
  v_device text := coalesce(p_device, 'other');
  v_link uuid := '00000000-0000-0000-0000-000000000000'::uuid;
begin
  if p_event is null or p_event not in ('view', 'click') then
    return;
  end if;

  if v_source not in (
    '', 'qr', 'google', 'bing', 'duckduckgo', 'instagram', 'facebook', 'x', 'tiktok',
    'youtube', 'linkedin', 'pinterest', 'reddit', 'whatsapp', 'telegram', 'snapchat',
    'threads', 'github', 'discord', 'email', 'other'
  ) then
    v_source := 'other';
  end if;

  if v_device not in ('mobile', 'tablet', 'desktop', 'other') then
    v_device := 'other';
  end if;

  select p.user_id
    into v_user_id
  from public.profiles p
  where p.username = lower(p_username)
    and p.is_published
    and p.onboarding_complete;

  if v_user_id is null then
    return;
  end if;

  if p_event = 'click' then
    if p_link_id is null then
      return;
    end if;
    if not exists (
      select 1
      from public.links l
      where l.id = p_link_id
        and l.user_id = v_user_id
        and l.kind in ('link', 'embed')
        and l.is_active
        and not l.is_archived
    ) then
      return;
    end if;
    v_link := p_link_id;
  end if;

  insert into public.analytics_daily as a (user_id, day, event, link_id, source, device, hits)
  values (v_user_id, (now() at time zone 'utc')::date, p_event, v_link, v_source, v_device, 1)
  on conflict (user_id, day, event, link_id, source, device)
  do update set hits = a.hits + 1;
end;
$$;

revoke all on function public.record_page_event(text, text, uuid, text, text) from public;
grant execute on function public.record_page_event(text, text, uuid, text, text) to anon, authenticated;

-- 3. READ YOUR ANALYTICS (signed-in owners only; Free and Pro limits enforced here) --------
-- Free: at most the last 30 days, and no sources or devices.
-- Pro: up to 365 days, with sources and devices.
create or replace function public.get_analytics(p_from date, p_to date)
returns jsonb
language plpgsql
stable
security definer
set search_path = ''
as $$
declare
  v_sub text := auth.jwt() ->> 'sub';
  v_pro boolean;
  v_today date := (now() at time zone 'utc')::date;
  v_max_days integer;
  v_to date;
  v_from date;
  v_result jsonb;
begin
  if v_sub is null then
    raise exception 'not_authenticated';
  end if;

  v_pro := public.has_pro(v_sub);
  v_max_days := case when v_pro then 365 else 30 end;

  v_to := least(coalesce(p_to, v_today), v_today);
  v_from := greatest(coalesce(p_from, v_to - 29), v_to - (v_max_days - 1));
  if v_from > v_to then
    v_from := v_to;
  end if;

  select jsonb_build_object(
    'range', jsonb_build_object(
      'from', v_from,
      'to', v_to,
      'max_days', v_max_days,
      'is_pro', v_pro
    ),
    'totals', (
      select jsonb_build_object(
        'views', coalesce(sum(a.hits) filter (where a.event = 'view'), 0),
        'clicks', coalesce(sum(a.hits) filter (where a.event = 'click'), 0)
      )
      from public.analytics_daily a
      where a.user_id = v_sub
        and a.day between v_from and v_to
    ),
    'daily', (
      select coalesce(
        jsonb_agg(
          jsonb_build_object('day', d.day, 'views', d.views, 'clicks', d.clicks)
          order by d.day
        ),
        '[]'::jsonb
      )
      from (
        select gs.d::date as day,
               coalesce(sum(a.hits) filter (where a.event = 'view'), 0) as views,
               coalesce(sum(a.hits) filter (where a.event = 'click'), 0) as clicks
        from generate_series(v_from::timestamp, v_to::timestamp, interval '1 day') as gs(d)
        left join public.analytics_daily a
          on a.user_id = v_sub and a.day = gs.d::date
        group by gs.d
      ) d
    ),
    'links', (
      select coalesce(
        jsonb_agg(
          jsonb_build_object('link_id', t.link_id, 'clicks', t.clicks)
          order by t.clicks desc
        ),
        '[]'::jsonb
      )
      from (
        select a.link_id, sum(a.hits) as clicks
        from public.analytics_daily a
        where a.user_id = v_sub
          and a.event = 'click'
          and a.day between v_from and v_to
        group by a.link_id
      ) t
    ),
    'sources', case when v_pro then (
      select coalesce(
        jsonb_agg(
          jsonb_build_object('source', s.source, 'views', s.views, 'clicks', s.clicks)
          order by s.views desc, s.clicks desc
        ),
        '[]'::jsonb
      )
      from (
        select a.source,
               coalesce(sum(a.hits) filter (where a.event = 'view'), 0) as views,
               coalesce(sum(a.hits) filter (where a.event = 'click'), 0) as clicks
        from public.analytics_daily a
        where a.user_id = v_sub
          and a.day between v_from and v_to
        group by a.source
      ) s
    ) else null end,
    'devices', case when v_pro then (
      select coalesce(
        jsonb_agg(
          jsonb_build_object('device', x.device, 'views', x.views, 'clicks', x.clicks)
          order by x.views desc, x.clicks desc
        ),
        '[]'::jsonb
      )
      from (
        select a.device,
               coalesce(sum(a.hits) filter (where a.event = 'view'), 0) as views,
               coalesce(sum(a.hits) filter (where a.event = 'click'), 0) as clicks
        from public.analytics_daily a
        where a.user_id = v_sub
          and a.day between v_from and v_to
        group by a.device
      ) x
    ) else null end
  )
  into v_result;

  return v_result;
end;
$$;

revoke all on function public.get_analytics(date, date) from public, anon;
grant execute on function public.get_analytics(date, date) to authenticated;

  {
    "range":   { "from": "YYYY-MM-DD", "to": "YYYY-MM-DD", "max_days": 30 | 365, "is_pro": boolean },

4. PRIVACY DESIGN (WHAT IS AND IS NOT COLLECTED)
=====================================================================
Collected (and only this): for a public page, one counter increment per view or per click, with the page, the UTC day, the link (for clicks), a source from the fixed list, and a device type from the fixed list.
Never collected or sent: IP address, user-agent string, full referrer URL or hostname, language, screen size, time of day, any identifier, anything from the visitor's storage.

Rules enforced in the client BEFORE any request is made (src/lib/analytics/shouldTrack.ts). shouldTrack() returns false when ANY of these is true:
1. Do Not Track is on: navigator.doNotTrack === "1" or window.doNotTrack === "1" or navigator.msDoNotTrack === "1".
2. Global Privacy Control is on: (navigator as unknown as { globalPrivacyControl?: boolean }).globalPrivacyControl === true (use a typed guard, never "any").
3. The visitor looks automated: navigator.webdriver === true, or the user-agent string matches /bot|crawl|spider|headless|lighthouse|pagespeed|prerender|phantomjs|puppeteer|playwright/i. (Read the user agent locally only; never send it.)
4. The page owner is viewing their own page (Section 5.4).
5. Tracking has been disabled by analyticsState.enabled being false (for example while the Supabase configuration is missing).
Views are additionally sent only while the document is visible: if document.visibilityState is not "visible" when the page is ready, wait for the first visibilitychange to "visible" (this skips prefetching and background tabs). Send each view at most once per page mount (use a ref; safe under React StrictMode double invocation).

- SOURCE_LABELS for display: "" Direct, qr "QR code", google "Google", bing "Bing", duckduckgo "DuckDuckGo", instagram "Instagram", facebook "Facebook", x "X", tiktok "TikTok", youtube "YouTube", linkedin "LinkedIn", pinterest "Pinterest", reddit "Reddit", whatsapp "WhatsApp", telegram "Telegram", snapchat "Snapchat", threads "Threads", github "GitHub", discord "Discord", email "Email", other "Other".
- parseSourceParam(search: string): TrackSource | null reads, in this priority, the query parameters "src", "utm_source" and "ref"; lowercases and trims the value; returns it only if it is in TRACK_SOURCES and not "" (otherwise null). Unknown values are ignored (never stored).
- classifyReferrer(referrer: string, ownHost: string): TrackSource. Rules:
  - Empty or unparsable referrer: "".
  - android-app:// referrers map by package: com.instagram.android instagram; com.facebook.katana and com.facebook.orca facebook; com.twitter.android x; com.zhiliaoapp.musically and com.ss.android.ugc.trill tiktok; com.google.android.youtube youtube; com.linkedin.android linkedin; com.reddit.frontpage reddit; com.whatsapp whatsapp; org.telegram.messenger telegram; com.snapchat.android snapchat; com.google.android.gm email; com.discord discord; com.pinterest pinterest; com.google.android.googlequicksearchbox google; anything else "other".
  - Otherwise take the hostname (lowercase, without a leading "www."). If it equals ownHost or ends with "." plus ownHost, return "" (our own site is direct).
  - Hostname mapping (exact host or subdomain of): google: any host matching /(^|\.)google\.[a-z.]+$/ except mail.google.com (email); bing.com bing; duckduckgo.com duckduckgo; instagram.com and l.instagram.com instagram; facebook.com, l.facebook.com, lm.facebook.com, m.facebook.com, fb.com, fb.me facebook; x.com, twitter.com, t.co x; tiktok.com tiktok; youtube.com, m.youtube.com, youtu.be youtube; linkedin.com, lnkd.in linkedin; pinterest.com, pin.it, and any pinterest.* host pinterest; reddit.com, out.reddit.com reddit; whatsapp.com, web.whatsapp.com, wa.me whatsapp; telegram.org, web.telegram.org, t.me telegram; snapchat.com snapchat; threads.net and threads.com threads; github.com github; discord.com, discord.gg discord; mail.google.com, outlook.live.com, outlook.office.com, outlook.office365.com email; any other host "other".
- resolveSource(): the source for the current visit: parseSourceParam(location.search) if not null, otherwise classifyReferrer(document.referrer, location.hostname). Compute once per page mount and reuse for the view and every click on that page.
- Put short example inputs and expected outputs as comments at the top of the file (at least ten, including a malformed one).

5.2 device.ts
detectDevice(userAgent: string): "mobile" | "tablet" | "desktop" | "other". Order: tablet when /iPad|Tablet|PlayStation|Kindle|Silk/i matches, or when /Android/i matches and /Mobile/i does not; mobile when /Mobi|iPhone|iPod|Android.*Mobile|Windows Phone/i matches; desktop when /Windows|Macintosh|Mac OS X|Linux|CrOS|X11/i matches; otherwise "other". An iPad that reports a Macintosh user agent is treated as desktop (do not try to detect it). Computed locally; the string itself is never sent.

5.3 track.ts
- analyticsState: a module-level object { enabled: boolean; username: string | null; source: TrackSource | null } with setters setAnalyticsContext({ username, source, enabled }) used by the public page. Default enabled true, username null.
- trackView(username, source): if shouldTrack() is false return. Otherwise schedule the call with requestIdleCallback (fallback setTimeout 0) and send recordPageEvent({ username, event: "view", linkId: null, source, device }). Fire and forget: wrap in try/catch, ignore the result, never await in the render path, never log.
- trackClick(username, linkId, source): the same, with event "click".
- Both validate arguments (username passes validateUsername, linkId is a uuid-shaped string) and do nothing otherwise.

5.4 Excluding the owner
The public page must not wait for Clerk. Rule: if Clerk finishes loading within 1200 ms of the page being ready and the signed-in person's username equals the page username, tracking is disabled for this page mount (setAnalyticsContext enabled false); otherwise tracking proceeds. Implementation: in PublicProfilePage, read Clerk's loaded state and username through the existing session hook; start a 1200 ms timer when the page is found; send the view when Clerk reports loaded (after the owner check) or when the timer fires, whichever comes first, and only once. Clicks use the same flag (a click before the decision is treated as tracked unless the owner flag has already been set). If Clerk or Supabase is not configured, skip the owner check.

5.5 The click seam
Implement trackLinkClick(block) in src/lib/analytics-seam.ts (the Step 3 no-op) so it calls trackClick(analyticsState.username, block.id, analyticsState.source) for blocks of kind "link" or "embed". Remove the "plugs in here" comment and replace it with a one-line description. It must stay safe to call from any click handler and must never throw.

6.3 Ranges (ranges.ts)
  RANGES = { "7d": { days: 7, bucket: "day", pro: false, label: "7 days" }, "30d": { days: 30, bucket: "day", pro: false, label: "30 days" }, "90d": { days: 90, bucket: "week", pro: true, label: "90 days" }, "12m": { days: 365, bucket: "month", pro: true, label: "12 months" } }
  rangeToDates(key): { from, to } where to = todayUtc() and from = addDaysUtc(to, -(days - 1)).
Default range: "30d".

6.4 The query (useAnalytics(rangeKey))
- Key: ["analytics", userId, from, to] (userId from the session hook). Enabled only when signed in, the profile row exists and Supabase is configured.
- Calls getAnalytics with the dates from rangeToDates. Result mapped with analyticsFromJson (null becomes an error state).
- staleTime 60 seconds, refetchOnWindowFocus true, retry once (not for not_authenticated). Keep previous data while a new range loads (placeholderData: keepPreviousData behavior) so the chart does not flash empty.
- If a Free account requests a Pro-only range, never send the request: the UI intercepts it (Section 9.3). If it still happens, the database clamps it and the UI renders what it receives.
- On sign-out the existing query-cache clear applies.

6.5 Bucketing (buckets.ts)
buildBuckets(daily, bucket): Bucket[] where Bucket = { key: string; startDay: string; label: string; views: number; clicks: number }.
- "day": one bucket per day; label formatDayLabel.
- "week": group days into weeks starting on Monday (UTC); the first and last buckets may be partial; label formatDayLabel(startDay).
- "month": group by UTC calendar month; label formatMonthLabel(startDay).
Sums are exact (no rounding). Buckets are ascending and contiguous.

6.6 Chart math (chart.ts)
niceMax(value): returns 4 when value is 4 or less; otherwise rounds up to 1, 2 or 5 times a power of ten (for example 7 becomes 10, 13 becomes 20, 48 becomes 50, 130 becomes 200). yTicks(max): [0, max / 2, max]. Provide a few example values as comments.
formatCtr(clicks, views): "–" when views is 0; otherwise the percentage with one decimal and a trailing "%", capped at "100%" (clicks can exceed views when some views are not counted).

13. SECURITY AND PRIVACY REQUIREMENTS (NON-NEGOTIABLE)
=====================================================================
1. All earlier rules still apply (publishable key only; no supabase.auth.*; visitors only call public RPCs; owner data only through the Clerk-token client; no logging of user data, tokens or raw errors; isSafeHref for every stored URL; no dangerouslySetInnerHTML).
2. The tracking request contains exactly: username, event, link id (clicks only), source, device. Nothing else. Never add timestamps, user agent, language, screen data, referrer text, identifiers or random tokens.
3. The raw referrer and the user-agent string are read locally, reduced to an allow-listed category, and discarded. Never send, store or log them.
4. Unknown values from the URL (src, utm_source, ref) are ignored. Never write them into the page, storage, logs or requests.
5. No cookies, no localStorage, no sessionStorage, no IndexedDB, no fingerprinting for analytics. The only state is in memory for the current page mount.
6. Respect Do Not Track and Global Privacy Control. Never count the owner's own visits or detected bots.
7. get_analytics is called only with the Clerk-token client and never with a user id from the URL or input.
8. Analytics values and labels render as React text nodes. Chart tooltips and tables never use innerHTML. SVG is generated by your components, never from strings.
9. No third-party analytics scripts, pixels, beacons or hidden iframes. No public counters on public pages: view and click numbers are visible to the owner only.
10. Do not build client-side rate limiting or "fraud protection" that gives a false sense of security. The counters are indicative, and the database bounds their size.
11. Do not claim "no data is collected". Wording in the product is limited to the exact strings in Section 15.

19. COMMON FAILURE MODES (SELF-CHECK)
=====================================================================
1. Sending the raw referrer or user agent to the database, or logging either.
2. Using cookies, localStorage or sessionStorage "just to avoid double counting".
3. Counting views twice (StrictMode double effect, or the 60-second refetch) or counting the owner's own visits.
4. Letting tracking block rendering or navigation, throw errors, or show a message when blocked.
5. Making Free-account gating a UI-only trick (the database already returns null sources and clamps ranges; render what you receive).
6. Charts that overflow at 320px, labels that overlap, or text that blurs because the SVG was scaled.
7. A chart that relies on color alone, or that cannot be used by keyboard.
8. Bars with too little contrast (use the outlined style from Section 9.5).
9. Reflecting unknown query parameters into the page.
10. Hard-coding the domain or the support email, or reintroducing the name "ivio".
11. Showing click counts in the Links tab by adding a blocking request or an error state.
12. Adding scope: unique visitors, countries, CSV export, custom date ranges, share-preview metadata, billing.
