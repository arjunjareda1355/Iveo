1. WHY STEP 4 IS SPLIT INTO PARTS
You asked for four big things: QR code and share previews, link extras (scheduling, embeds, thumbnails), analytics, and Pro billing. Building all of them in one prompt makes the result buggy, so Step 4 is split. Each part works on its own and builds on the last:

  4A (this file)  Link extras (thumbnails, featured layout, scheduling, embeds), QR code and share sheet, and the "plan" foundation that decides what is Free and what is Pro.
  4B              Analytics: page views and link clicks (basic for Free, deeper charts for Pro).
  4C              Share previews (the card shown when your link is pasted in WhatsApp, X, iMessage) plus hosting hardening: account-deletion cleanup and username sync. This one depends on where you host the site.
  4D              Pro billing (Clerk Billing), which switches the plan automatically when someone pays.
  Later           The two remaining Pro items listed on your pricing section: password-protected links, and email/phone collection with CSV export.

Billing comes last on purpose: the paid features have to exist before there is anything to sell, and 4A builds the lock that billing will later open.

2. WHAT 4A ADDS
- Link thumbnails (small image on a link) and a "Featured" layout (large image card). Free.
- Scheduling: show a link from a date and hide it after a date. Pro.

- A "plan" for each account (Free or Pro) enforced by the database itself, plus a "remove the ivio mark" option on your public page. Pro.
Until Step 4D, nobody can buy Pro. You will switch your own account to Pro by hand for testing (see below).

-- 2. PLAN CHECK (the single place that decides who is Pro) ---------------
-- Step 4D replaces the body of this function so billing decides the plan.
create or replace function public.has_pro(p_user_id text)
returns boolean
language sql
stable
security definer
set search_path = ''
as $$
  select coalesce(
    (select p.plan = 'pro' from public.profiles p where p.user_id = p_user_id),
    false
  );
$$;

revoke all on function public.has_pro(text) from public, anon, authenticated;

  add constraint links_layout_valid check (layout in ('classic', 'featured'));

alter table public.links
  add constraint links_embed_provider_valid
  check (embed_provider is null or embed_provider in ('youtube', 'spotify', 'soundcloud'));

  add constraint links_schedule_order
  check (start_at is null or end_at is null or end_at > start_at);

alter table public.links
  add constraint links_schedule_kinds
  check ((start_at is null and end_at is null) or kind in ('link', 'embed'));

alter table public.links
  add constraint links_thumbnail_path_ok check (
    thumbnail_path is null or (
      char_length(thumbnail_path) <= 200
      and thumbnail_path ~ '^[A-Za-z0-9_]+/[0-9a-f-]{36}\.(webp|jpg)$'
      and split_part(thumbnail_path, '/', 1) = user_id
    )
  );

alter table public.links
  add constraint links_thumbnail_only_links
  check (thumbnail_path is null or kind = 'link');

alter table public.links
  add constraint links_featured_needs_image
  check (layout = 'classic' or (layout = 'featured' and kind = 'link' and thumbnail_path is not null));

alter table public.links
  add constraint links_shape_by_kind check (
       (kind = 'link'    and url is not null and char_length(title) between 1 and 60 and embed_provider is null)
    or (kind = 'header'  and url is null     and char_length(title) between 1 and 40 and embed_provider is null)
    or (kind = 'divider' and url is null     and title = ''                          and embed_provider is null)
    or (kind = 'embed'   and url is not null and char_length(title) <= 60 and embed_provider is not null
         and (
              (embed_provider = 'youtube'    and url ~* '^https://(www\.|m\.)?(youtube\.com|youtu\.be)/')
           or (embed_provider = 'spotify'    and url ~* '^https://open\.spotify\.com/')
           or (embed_provider = 'soundcloud' and url ~* '^https://soundcloud\.com/')
         ))
  );

-- 5. PRO ENFORCEMENT TRIGGERS ---------------------------------------------
-- Writing a schedule or an embed requires Pro. Clearing a schedule, moving,
-- hiding, archiving and deleting are always allowed (so downgraded accounts
-- can still tidy up).
create or replace function public.enforce_pro_links()
returns trigger
language plpgsql
security definer
set search_path = ''
as $$
declare
  wants_pro boolean;
begin
  if tg_op = 'INSERT' then
    wants_pro := new.kind = 'embed' or new.start_at is not null or new.end_at is not null;
  else
    wants_pro :=
      (new.kind = 'embed' and (
         new.url is distinct from old.url or new.embed_provider is distinct from old.embed_provider))
      or (new.start_at is not null and new.start_at is distinct from old.start_at)
      or (new.end_at is not null and new.end_at is distinct from old.end_at);
  end if;

  if wants_pro and not public.has_pro(new.user_id) then
    raise exception 'pro_required';
  end if;
  return new;
end;
$$;

drop trigger if exists links_pro_check on public.links;
create trigger links_pro_check
  before insert or update on public.links
  for each row execute function public.enforce_pro_links();

create or replace function public.enforce_pro_profiles()
returns trigger
language plpgsql
security definer
set search_path = ''
as $$
begin
  if new.hide_ivio_footer = true
     and (tg_op = 'INSERT' or new.hide_ivio_footer is distinct from old.hide_ivio_footer)
     and not public.has_pro(new.user_id) then
    raise exception 'pro_required';
  end if;
  return new;
end;
$$;

drop trigger if exists profiles_pro_check on public.profiles;
create trigger profiles_pro_check
  before insert or update on public.profiles
  for each row execute function public.enforce_pro_profiles();

-- 6. PUBLIC PAGE FUNCTION (replaces the v1 version; same name and inputs) ---
create or replace function public.get_public_page(p_username text)
returns jsonb
language sql
stable
security definer
set search_path = ''
as $$
  select jsonb_build_object(
    'profile', jsonb_build_object(
      'username', p.username,
      'display_name', p.display_name,
      'bio', p.bio,
      'avatar_url', p.avatar_url,
      'vibe_id', p.vibe_id,
      'button_shape', p.button_shape,
      'socials', p.socials,
      'hide_from_search', p.hide_from_search,
      'hide_footer', (p.hide_ivio_footer and public.has_pro(p.user_id))
    ),
    'links', coalesce(
      (
        select jsonb_agg(
          jsonb_build_object(
            'id', l.id,
            'kind', l.kind,
            'title', l.title,
            'url', l.url,
            'icon', l.icon,
            'thumbnail_path', l.thumbnail_path,
            'layout', l.layout,
            'embed_provider', l.embed_provider
          )
          order by l.position, l.created_at
        )
        from public.links l
        where l.user_id = p.user_id
          and l.is_active
          and not l.is_archived
          and (l.start_at is null or l.start_at <= now())
          and (l.end_at is null or l.end_at > now())
          and (l.kind <> 'embed' or public.has_pro(p.user_id))
          and ((l.start_at is null and l.end_at is null) or public.has_pro(p.user_id))
      ),
      '[]'::jsonb
    )
  )
  from public.profiles p
  where p.username = lower(p_username)
    and p.is_published
    and p.onboarding_complete;
$$;

revoke all on function public.get_public_page(text) from public;
grant execute on function public.get_public_page(text) to anon, authenticated;

-- 7. STORAGE: public bucket for link images ---------------------------------
-- Anyone can view an image by its address. Only the owner can add, replace
-- or delete files inside the folder named after their own user id.
insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
values ('link-images', 'link-images', true, 524288, array['image/webp', 'image/jpeg'])
on conflict (id) do update
  set public = excluded.public,
      file_size_limit = excluded.file_size_limit,
      allowed_mime_types = excluded.allowed_mime_types;

drop policy if exists link_images_select_own on storage.objects;
create policy link_images_select_own on storage.objects
  for select to authenticated
  using (
    bucket_id = 'link-images'
    and (storage.foldername(name))[1] = (select auth.jwt() ->> 'sub')
  );

drop policy if exists link_images_insert_own on storage.objects;
create policy link_images_insert_own on storage.objects
  for insert to authenticated
  with check (
    bucket_id = 'link-images'
    and (storage.foldername(name))[1] = (select auth.jwt() ->> 'sub')
  );

drop policy if exists link_images_update_own on storage.objects;
create policy link_images_update_own on storage.objects
  for update to authenticated
  using (
    bucket_id = 'link-images'
    and (storage.foldername(name))[1] = (select auth.jwt() ->> 'sub')
  )
  with check (
    bucket_id = 'link-images'
    and (storage.foldername(name))[1] = (select auth.jwt() ->> 'sub')
  );

drop policy if exists link_images_delete_own on storage.objects;
create policy link_images_delete_own on storage.objects
  for delete to authenticated
  using (
    bucket_id = 'link-images'
    and (storage.foldername(name))[1] = (select auth.jwt() ->> 'sub')
  );

7.4 Image processing (src/lib/image-processing.ts)
processImage(file): Promise<{ blob: Blob; type: "image/webp" | "image/jpeg"; width: number; height: number }>
1. Reject if file.type is not exactly image/png, image/jpeg or image/webp ("unsupported"). Reject if file.size is over 8 MB ("too_large_input"). GIF, SVG, HEIC and everything else are rejected (SVG can carry scripts).
2. Decode with createImageBitmap(file, { imageOrientation: "from-image" }) (fall back to an Image element when unavailable). Reject below 64 pixels on the shorter side ("too_small").
3. Scale down so the longest side is at most 1280 pixels (never upscale). Draw on a canvas.
4. Encode as image/webp at quality 0.82. If the browser returns a different type (no webp support), fill the canvas white first and encode as image/jpeg at quality 0.85.
5. If the blob is larger than 500,000 bytes, lower the quality in steps of 0.1 down to 0.5; if it is still too large, scale the canvas by 0.8 and retry (at most 3 rounds); then fail with "too_large_output".
6. Re-encoding strips all metadata (location, camera data). Say nothing about it in the UI.
The function never touches the network and never throws untyped errors: it throws or returns typed codes that the UI maps to the messages in 7.2.

7.5 Upload, replace and remove flows
- Choose or drop a file: processImage, then uploadLinkImage, then setBlockImage(blockId, { thumbnailPath: newPath, layout: currentLayoutOrClassic }) with optimistic update. On success, remove the previous object with removeLinkImage (best effort). If setBlockImage fails after a successful upload, remove the new object (best effort) and show the error.
- Remove: setBlockImage(blockId, { thumbnailPath: null, layout: "classic" }) optimistically; on success removeLinkImage(oldPath) (best effort).
- Delete a link that has an image: after the delete succeeds, removeLinkImage(oldPath) (best effort).

9.1 Supported sources

9.2 URL parsing (src/lib/embeds.ts)
parseEmbedUrl(input: string): ParsedEmbed | null, where ParsedEmbed = { provider: "youtube" | "spotify" | "soundcloud"; canonicalUrl: string; embedSrc: string; label: string (for example "YouTube video", "Spotify track", "SoundCloud set"); height: number | null; aspect: string | null }.
General rules: trim; the string must parse with new URL(); the protocol must be https: (a link without a scheme gets "https://" prepended first); the hostname is compared exactly (after lowercasing) against the allowed hosts below; the embed address is BUILT from the extracted id, never copied from the pasted link. Anything else returns null.

YouTube
- Hosts: youtube.com, www.youtube.com, m.youtube.com, youtu.be.
- Video id sources: youtu.be/<id>; /watch?v=<id>; /shorts/<id>; /embed/<id>; /live/<id>. The id must match ^[A-Za-z0-9_-]{11}$.
- Optional start time from the t or start query parameter when it is plain seconds (digits only, at most 86400); otherwise ignore it.
- canonicalUrl: https://www.youtube.com/watch?v=<id> (add &t=<n>s when a start time exists).
- embedSrc: https://www.youtube-nocookie.com/embed/<id>?rel=0&playsinline=1 (add &start=<n> when a start time exists). Never add autoplay.
- aspect "16 / 9", height null. label "YouTube video".
- Playlist-only links and channel links return null.

Spotify
- Host: open.spotify.com (an optional locale prefix such as /intl-de/ before the type is allowed and ignored).
- Path: /<type>/<id> with type one of track, episode, album, playlist, show, artist and id matching ^[A-Za-z0-9]{22}$. Query strings are ignored.
- canonicalUrl: https://open.spotify.com/<type>/<id>.
- embedSrc: https://open.spotify.com/embed/<type>/<id>?utm_source=generator.
- height 152 for track and episode, 352 for album, playlist, show and artist. aspect null. label "Spotify <type>".
- spotify:track:... URIs and spotify.link short links return null.

SoundCloud
- Host: soundcloud.com (not on.soundcloud.com, not m.soundcloud.com).
- Path: /<user>/<track> (two segments) or /<user>/sets/<set> (three segments with the middle one "sets"). Each segment matches ^[A-Za-z0-9_-]+$. Query strings are ignored. Profile-only links return null.
- canonicalUrl: https://soundcloud.com/<path>.
- embedSrc: https://w.soundcloud.com/player/?url=<encodeURIComponent(canonicalUrl)>&color=%230a0a0a&auto_play=false&hide_related=true&show_comments=false&show_user=true&show_reposts=false&show_teaser=false&visual=false.
- height 166 for a track, 300 for a set. aspect null. label "SoundCloud track" or "SoundCloud set".
The function is pure. It must be unit-testable with plain strings. Include a short block of example inputs and expected outputs as comments at the top of the file (three valid and three invalid per provider).

- Downgraded accounts: existing embeds and scheduled items remain in the dashboard (locked and labeled, Section 8.4), are not shown to visitors, and can be edited for non-Pro fields, reordered, hidden, archived and deleted. Their schedules can be cleared.
- Past schedules: an item whose end time has passed shows "Ended" in the dashboard and is not shown on the page. It can be rescheduled (Pro) or archived.
- Missing or deleted images: if an image URL fails to load on the dashboard or the page, fall back to the icon or collapse the image area (Section 6).
- Offline banner, DataLoadError and session-expiry behavior from Step 3 apply to every new request.
- Share sheet when the username is missing (should not happen): disable the buttons and show the DataLoadError variant.
- QR download blocked by the browser: nothing else breaks; the QR image remains visible so it can be saved with a long press.

15. SECURITY REQUIREMENTS (NON-NEGOTIABLE)
=====================================================================
1. All Step 3 rules still apply (publishable key only; no supabase.auth.*; visitors only use the two public RPCs; owner data only through the Clerk-token client; no logging of user data, tokens or raw errors; isSafeHref for every stored URL; no dangerouslySetInnerHTML; external links with rel="noopener noreferrer nofollow").
2. The app never writes the plan. Never include "plan" in any insert, update or upsert payload.
3. Uploads: only after processImage re-encodes the file; the original file is never uploaded. SVG, GIF, HEIC and anything not PNG, JPEG or WebP is rejected before processing. The storage path always starts with the Clerk user id and never uses the original file name.
4. Embed addresses: the iframe src is ALWAYS built by parseEmbedUrl from validated ids on the allowed hosts. Never put a stored or pasted URL directly into an iframe src. Never render an iframe for a provider or host that is not on the allow-list. Iframes use the sandbox and referrerPolicy from Section 9.5.
5. The QR image is rendered through an <img> with a data URL, never as inline SVG markup.
6. Image <img> elements keep referrerPolicy "no-referrer". Only embed iframes use "strict-origin-when-cross-origin".
7. No third-party scripts, SDKs or trackers are added for embeds or QR codes. Embeds load nothing until the visitor presses Play.
8. Dates are parsed with new Date() and validated (isNaN checks) before use; invalid values are treated as empty.
9. Never expose plan, user ids, emails or storage paths of other people in the UI.
10. Do not build client-side workarounds for Pro enforcement. The database decides; the UI mirrors it.

21. COMMON FAILURE MODES (SELF-CHECK)
=====================================================================
1. Sending "plan" (or any column outside the allowed list) in a profile payload.
2. Putting a pasted URL straight into an iframe src, or loading players before Play.
3. Forgetting referrerPolicy "strict-origin-when-cross-origin" on embed iframes (YouTube then refuses to play), or adding a page-wide no-referrer policy.
4. Uploading the original file instead of the re-encoded blob, or trusting the file extension.
5. Letting "Featured" be saved without an image (the database rejects it) or leaving a stale layout after removing the image.
6. Dashboard preview that disagrees with the public page about schedules or embeds (use isBlockVisibleNow).
7. Hiding the "Report this page" link when the footer mark is hidden.
8. Using window.location.origin for QR codes and copied links.
9. Injecting QR SVG markup into the DOM instead of using an <img> data URL.
10. Layout shift when images, embeds or the QR code load.
11. Blocking downgraded users from deleting, archiving or clearing schedules.
12. Adding scope: analytics, share-preview metadata, billing, password links, contact collection.
