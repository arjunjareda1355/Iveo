2. WHAT 4E ADDS
Password-protected links (Pro)
- You can set a password on any normal link. On your public page the link shows a small lock. When a visitor presses it, a dialog asks for the password. If it is right, the visitor gets an "Open link" button. If it is wrong, nothing is revealed.
- The real address of a protected link is NEVER sent to visitors until the password is correct. The password is stored only as a one-way hash, checked inside the database, and can never be shown again (only replaced or removed).
- Repeated wrong guesses are slowed down automatically.
Email and phone collection (Pro)
- A new block called a signup form. You choose what it collects (email, phone, or both), the heading, an optional short description, the button label and the consent sentence the visitor must tick.
- A new Contacts tab in the dashboard: search, delete, and Download CSV.
- Spam protection (a hidden trap field and rate limits) and duplicate protection.

3. PRIVACY AND LEGAL NOTES (READ THIS; IT IS NOT LEGAL ADVICE)
- Once a signup form exists, iveo stores personal data of your users' visitors (emails and phone numbers). Your users decide why they collect it; iveo stores it for them. Laws like GDPR and similar rules apply. Have a lawyer review your Terms and Privacy Policy BEFORE you turn on Pro for the public.
- Your Privacy page is still a placeholder. At minimum it should explain: what the signup forms collect, that the page owner (not iveo) decides how the data is used, how long data is kept, how people can ask for deletion, and where the data is stored (your Supabase region). A starting paragraph to hand to your lawyer:
    "Page owners can add signup forms to their iveo pages. When a visitor submits a form, iveo stores the details they enter (an email address and/or phone number), the consent text they agreed to, the time of submission and the page owner's form name. The page owner is responsible for how they use this data. iveo does not send messages to these contacts. Page owners can export or delete their contacts at any time, and deleting an account deletes all of its contacts. To ask for removal of your details from a page owner's list, contact the page owner or email <your support address>."
- The consent checkbox is mandatory. The consent sentence is written by the page owner (a sensible default is provided), and a copy of the exact sentence the visitor agreed to is stored with each contact.
- Passwords on links protect where a link points, not the website behind it. Anyone who knows the password can pass the revealed address on.
- Please do not store any real visitor data while you test. Use your own email and phone number or made-up ones.

6. KNOWN LIMITS OF 4E (PLAN FOR THEM)
- There is no CAPTCHA yet. A hidden trap field and rate limits stop casual spam, but a determined attacker can still send some junk submissions (they are capped per form and per account). A CAPTCHA such as Cloudflare Turnstile is a good later addition.
- iveo does not email you when someone signs up and does not send emails or texts to contacts. Download the CSV and use your own email tool.
- There is no double opt-in, unsubscribe page or SMS verification. Phone numbers are checked for format only.
- Rate limits use the visitor's network address where the database can see it. A short-lived, one-way hash is used and deleted automatically; if the address is not available, only the per-link limit applies.
- Passwords cannot be recovered, only replaced. Visitors who have the revealed address can share it.
- Contacts are kept until the owner deletes them or the account is deleted.
- Each account can store up to 10,000 contacts and 500 blocks.

-- 0. EXTENSIONS ---------------------------------------------------------------
-- pgcrypto provides password hashing and hashing for rate limits.
create extension if not exists pgcrypto with schema extensions;

-- 1. RATE LIMITS (counters only; cleaned up automatically) -------------------
create table if not exists public.rate_limits (
  key text not null,
  bucket timestamptz not null,
  n integer not null default 0,
  primary key (key, bucket)
);
alter table public.rate_limits enable row level security;
revoke all on public.rate_limits from anon, authenticated;

-- Secret salt used when hashing network addresses (one row; never readable by the app).
create table if not exists public.rate_limit_salt (
  salt text not null
);
alter table public.rate_limit_salt enable row level security;
revoke all on public.rate_limit_salt from anon, authenticated;

insert into public.rate_limit_salt (salt)
select encode(extensions.gen_random_bytes(32), 'hex')
where not exists (select 1 from public.rate_limit_salt);

-- Counts one hit for a key in the current time window. Returns true while the
-- number of hits in this window is still within the allowance.
create or replace function public.rate_limit_hit(p_key text, p_window_seconds integer, p_max integer)
returns boolean
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_bucket timestamptz :=
    to_timestamp(floor(extract(epoch from now()) / p_window_seconds) * p_window_seconds);
  v_n integer;
begin
  insert into public.rate_limits as r (key, bucket, n)
  values (p_key, v_bucket, 1)
  on conflict (key, bucket) do update set n = r.n + 1
  returning r.n into v_n;

  if random() < 0.02 then
    delete from public.rate_limits where bucket < now() - interval '1 day';
  end if;

  return v_n <= p_max;
end;
$$;

revoke all on function public.rate_limit_hit(text, integer, integer) from public, anon, authenticated;

-- One-way hash of the caller's network address and browser, mixed with a secret
-- salt and a scope. Returns null when the address is not available.
create or replace function public.client_fingerprint(p_scope text)
returns text
language plpgsql
stable
security definer
set search_path = ''
as $$
declare
  v_headers json := coalesce(nullif(current_setting('request.headers', true), '')::json, '{}'::json);
  v_ip text := btrim(split_part(coalesce(v_headers ->> 'x-forwarded-for', v_headers ->> 'cf-connecting-ip', ''), ',', 1));
  v_ua text := coalesce(v_headers ->> 'user-agent', '');
  v_salt text;
begin
  if v_ip = '' then
    return null;
  end if;
  select s.salt into v_salt from public.rate_limit_salt s limit 1;
  return encode(
    extensions.digest(coalesce(v_salt, '') || '|' || v_ip || '|' || v_ua || '|' || coalesce(p_scope, ''), 'sha256'),
    'hex'
  );
end;
$$;

revoke all on function public.client_fingerprint(text) from public, anon, authenticated;

-- 2. LINKS: allow signup forms --------------------------------------------------
alter table public.links add column if not exists signup_config jsonb;

create or replace function public.signup_config_is_valid(c jsonb)
returns boolean
language sql
immutable
set search_path = ''
as $$
  select case
    when c is null or jsonb_typeof(c) <> 'object' then false
    when coalesce(c ->> 'collect', '') not in ('email', 'phone', 'both') then false
    when jsonb_typeof(c -> 'button') is distinct from 'string' then false
    when char_length(coalesce(c ->> 'button', '')) not between 1 and 20 then false
    when jsonb_typeof(c -> 'consent') is distinct from 'string' then false
    when char_length(coalesce(c ->> 'consent', '')) not between 1 and 200 then false
    when (c -> 'description') is not null
         and jsonb_typeof(c -> 'description') not in ('string', 'null') then false
    when char_length(coalesce(c ->> 'description', '')) > 120 then false
    else true
  end;
$$;

alter table public.links drop constraint if exists links_kind_valid;
alter table public.links drop constraint if exists links_shape_by_kind;
alter table public.links drop constraint if exists links_schedule_kinds;

alter table public.links
  add constraint links_kind_valid check (kind in ('link', 'header', 'divider', 'embed', 'signup'));

alter table public.links
  add constraint links_schedule_kinds
  check ((start_at is null and end_at is null) or kind in ('link', 'embed', 'signup'));

alter table public.links
  add constraint links_shape_by_kind check (
       (kind = 'link'    and url is not null and char_length(title) between 1 and 60
          and embed_provider is null and signup_config is null)
    or (kind = 'header'  and url is null and char_length(title) between 1 and 40
          and embed_provider is null and signup_config is null)
    or (kind = 'divider' and url is null and title = ''
          and embed_provider is null and signup_config is null)
    or (kind = 'embed'   and url is not null and char_length(title) <= 60
          and embed_provider is not null and signup_config is null
          and (
                (embed_provider = 'youtube'    and url ~* '^https://(www\.|m\.)?(youtube\.com|youtu\.be)/')
             or (embed_provider = 'spotify'    and url ~* '^https://open\.spotify\.com/')
             or (embed_provider = 'soundcloud' and url ~* '^https://soundcloud\.com/')
          ))
    or (kind = 'signup'  and url is null and char_length(title) between 1 and 60
          and embed_provider is null
          and signup_config is not null and public.signup_config_is_valid(signup_config))
  );

-- Pro enforcement now also covers signup forms (replaces the v2 function).
create or replace function public.enforce_pro_links()
returns trigger
language plpgsql
security definer
set search_path = ''
as $$
declare
  wants_pro boolean;
begin
  if tg_op = 'INSERT' then
    wants_pro := new.kind in ('embed', 'signup')
      or new.start_at is not null
      or new.end_at is not null;
  else
    wants_pro :=
      (new.kind = 'embed' and (
         new.url is distinct from old.url or new.embed_provider is distinct from old.embed_provider))
      or (new.kind = 'signup' and (
         new.signup_config is distinct from old.signup_config or new.title is distinct from old.title))
      or (new.start_at is not null and new.start_at is distinct from old.start_at)
      or (new.end_at is not null and new.end_at is distinct from old.end_at);
  end if;

  if wants_pro and not public.has_pro(new.user_id) then
    raise exception 'pro_required';
  end if;
  return new;
end;
$$;

-- 3. PASSWORD-PROTECTED LINKS -------------------------------------------------
-- Password hashes live in their own table that nobody can read directly.
create table if not exists public.link_secrets (
  link_id uuid primary key references public.links (id) on delete cascade,
  password_hash text not null,
  created_at timestamptz not null default now()
);
alter table public.link_secrets enable row level security;
revoke all on public.link_secrets from anon, authenticated;

-- Owner: set or change the password of one of their own normal links (Pro).
create or replace function public.set_link_password(p_link_id uuid, p_password text)
returns void
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_sub text := auth.jwt() ->> 'sub';
begin
  if v_sub is null then
    raise exception 'not_authenticated';
  end if;
  if p_password is null
     or char_length(p_password) not between 4 and 64
     or p_password <> btrim(p_password) then
    raise exception 'invalid_password';
  end if;
  if not public.has_pro(v_sub) then
    raise exception 'pro_required';
  end if;
  if not exists (
    select 1 from public.links l
    where l.id = p_link_id and l.user_id = v_sub and l.kind = 'link'
  ) then
    raise exception 'not_found';
  end if;

  insert into public.link_secrets (link_id, password_hash)
  values (p_link_id, extensions.crypt(p_password, extensions.gen_salt('bf', 10)))
  on conflict (link_id) do update
    set password_hash = excluded.password_hash,
        created_at = now();
end;
$$;

revoke all on function public.set_link_password(uuid, text) from public, anon;
grant execute on function public.set_link_password(uuid, text) to authenticated;

-- Owner: remove the password from one of their own links (always allowed).
create or replace function public.clear_link_password(p_link_id uuid)
returns void
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_sub text := auth.jwt() ->> 'sub';
begin
  if v_sub is null then
    raise exception 'not_authenticated';
  end if;
  delete from public.link_secrets s
  using public.links l
  where s.link_id = l.id
    and l.id = p_link_id
    and l.user_id = v_sub;
end;
$$;

revoke all on function public.clear_link_password(uuid) from public, anon;
grant execute on function public.clear_link_password(uuid) to authenticated;

-- Owner: which of my links have a password? (ids only, never hashes)
create or replace function public.get_protected_link_ids()
returns uuid[]
language sql
stable
security definer
set search_path = ''
as $$
  select coalesce(array_agg(s.link_id), '{}'::uuid[])
  from public.link_secrets s
  join public.links l on l.id = s.link_id
  where l.user_id = (auth.jwt() ->> 'sub');
$$;

revoke all on function public.get_protected_link_ids() from public, anon;
grant execute on function public.get_protected_link_ids() to authenticated;

-- Visitors: try a password. Returns {"ok": true, "url": "..."} or
-- {"ok": false, "reason": "wrong_password" | "locked" | "unavailable"}.
create or replace function public.unlock_link(p_link_id uuid, p_password text)
returns jsonb
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_fp text;
  v_url text;
  v_hash text;
  v_user_id text;
begin
  if p_link_id is null or p_password is null or char_length(p_password) > 64 then
    return jsonb_build_object('ok', false, 'reason', 'wrong_password');
  end if;

  if not public.rate_limit_hit('unlock:link:' || p_link_id::text, 600, 100) then
    return jsonb_build_object('ok', false, 'reason', 'locked');
  end if;

  v_fp := public.client_fingerprint(p_link_id::text);
  if v_fp is not null and not public.rate_limit_hit('unlock:client:' || v_fp, 600, 8) then
    return jsonb_build_object('ok', false, 'reason', 'locked');
  end if;

  select l.url, s.password_hash, l.user_id
    into v_url, v_hash, v_user_id
  from public.links l
  join public.link_secrets s on s.link_id = l.id
  join public.profiles p on p.user_id = l.user_id
  where l.id = p_link_id
    and l.kind = 'link'
    and l.is_active
    and not l.is_archived
    and (l.start_at is null or l.start_at <= now())
    and (l.end_at is null or l.end_at > now())
    and p.is_published
    and p.onboarding_complete;

  if v_hash is null or not public.has_pro(v_user_id) then
    return jsonb_build_object('ok', false, 'reason', 'unavailable');
  end if;

  if extensions.crypt(p_password, v_hash) = v_hash then
    return jsonb_build_object('ok', true, 'url', v_url);
  end if;

  return jsonb_build_object('ok', false, 'reason', 'wrong_password');
end;
$$;

revoke all on function public.unlock_link(uuid, text) from public;
grant execute on function public.unlock_link(uuid, text) to anon, authenticated;

-- 4. CONTACTS ---------------------------------------------------------------------
create table if not exists public.contacts (
  id uuid primary key default gen_random_uuid(),
  user_id text not null references public.profiles (user_id) on delete cascade,
  link_id uuid references public.links (id) on delete set null,
  form_title text not null default '',
  email text,
  phone text,
  consent_text text not null,
  source text not null default '',
  created_at timestamptz not null default now(),
  constraint contacts_email_format check (
    email is null or (char_length(email) <= 254 and email ~* '^[^@\s]+@[^@\s]+\.[^@\s]+$')
  ),
  constraint contacts_phone_format check (phone is null or phone ~ '^\+?[0-9]{7,15}$'),
  constraint contacts_has_contact check (email is not null or phone is not null),
  constraint contacts_consent_len check (char_length(consent_text) between 1 and 200),
  constraint contacts_form_title_len check (char_length(form_title) <= 60),
  constraint contacts_source_valid check (source in (
    '', 'qr', 'google', 'bing', 'duckduckgo', 'instagram', 'facebook', 'x', 'tiktok',
    'youtube', 'linkedin', 'pinterest', 'reddit', 'whatsapp', 'telegram', 'snapchat',
    'threads', 'github', 'discord', 'email', 'other'
  ))
);

create unique index if not exists contacts_user_email_key
  on public.contacts (user_id, lower(email)) where email is not null;
create unique index if not exists contacts_user_phone_key
  on public.contacts (user_id, phone) where phone is not null;
create index if not exists contacts_user_created_idx
  on public.contacts (user_id, created_at desc);

returns trigger

begin

-- Visitors: submit a signup form. Returns {"ok": true} or
-- {"ok": false, "reason": "consent_required" | "invalid_email" | "invalid_phone"
--   | "rate_limited" | "unavailable"}.
create or replace function public.submit_contact(
  p_username text,
  p_link_id uuid,
  p_email text,
  p_phone text,
  p_consent boolean,
  p_hp text default '',
  p_source text default ''
)
returns jsonb
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_fp text;
  v_user_id text;
  v_cfg jsonb;
  v_title text;
  v_collect text;
  v_email text;
  v_phone text;
  v_source text := coalesce(p_source, '');
begin
  -- Hidden trap field: bots fill it in. Pretend it worked and store nothing.
  if coalesce(p_hp, '') <> '' then
    return jsonb_build_object('ok', true);
  end if;

  if p_consent is not true then
    return jsonb_build_object('ok', false, 'reason', 'consent_required');
  end if;

  if p_link_id is null then
    return jsonb_build_object('ok', false, 'reason', 'unavailable');
  end if;

  if not public.rate_limit_hit('contact:link:' || p_link_id::text, 600, 60) then
    return jsonb_build_object('ok', false, 'reason', 'rate_limited');
  end if;

  v_fp := public.client_fingerprint(p_link_id::text);
  if v_fp is not null and not public.rate_limit_hit('contact:client:' || v_fp, 600, 5) then
    return jsonb_build_object('ok', false, 'reason', 'rate_limited');
  end if;

  select p.user_id, l.signup_config, l.title
    into v_user_id, v_cfg, v_title
  from public.profiles p
  join public.links l on l.user_id = p.user_id
  where p.username = lower(p_username)
    and p.is_published
    and p.onboarding_complete
    and l.id = p_link_id
    and l.kind = 'signup'
    and l.is_active
    and not l.is_archived
    and (l.start_at is null or l.start_at <= now())
    and (l.end_at is null or l.end_at > now());

  if v_user_id is null or not public.has_pro(v_user_id) then
    return jsonb_build_object('ok', false, 'reason', 'unavailable');
  end if;

  v_collect := v_cfg ->> 'collect';
  v_email := nullif(lower(btrim(coalesce(p_email, ''))), '');
  v_phone := nullif(regexp_replace(coalesce(p_phone, ''), '[\s().-]', '', 'g'), '');

  if v_collect in ('email', 'both') then
    if v_email is null
       or char_length(v_email) > 254
       or v_email !~* '^[^@\s]+@[^@\s]+\.[^@\s]+$' then
      return jsonb_build_object('ok', false, 'reason', 'invalid_email');
    end if;
  else
    v_email := null;
  end if;

  if v_collect in ('phone', 'both') then
    if v_phone is null or v_phone !~ '^\+?[0-9]{7,15}$' then
      return jsonb_build_object('ok', false, 'reason', 'invalid_phone');
    end if;
  else
    v_phone := null;
  end if;

  if v_source not in (

create or replace function public.get_public_page(p_username text)
returns jsonb
language sql
stable
security definer
set search_path = ''
as $$
  select jsonb_build_object(
    'profile', jsonb_build_object(
      'username', p.username,
      'display_name', p.display_name,
      'bio', p.bio,
      'avatar_url', p.avatar_url,

      'hide_footer', (p.hide_ivio_footer and public.has_pro(p.user_id))

    'links', coalesce(
      (
        select jsonb_agg(
          jsonb_build_object(
            'id', l.id,
            'kind', l.kind,
            'title', l.title,
            'url', case when s.link_id is not null then null else l.url end,

            'layout', l.layout,

                'consent', l.signup_config ->> 'consent',

      '[]'::jsonb

  from public.profiles p
  where p.username = lower(p_username)
    and p.is_published
    and p.onboarding_complete;

12. CSV EXPORT
=====================================================================
12.1 Behavior
"Download CSV" calls fetchContactsForExport (pages of 1000, at most 20 pages), builds the file, and downloads "iveo-contacts-<username>-<YYYY-MM-DD>.csv" (UTC date) with a Blob (type "text/csv;charset=utf-8") and a temporary anchor (revoke the object URL on the next tick). While running the button shows the spinner state and the label stays. Success toast "CSV downloaded". If the cap was reached, toast "Exported the first 20,000 contacts." Failure toast "Couldn't export contacts. Try again." Never write contacts to any storage.

12.2 Format (src/lib/csv.ts, buildContactsCsv(rows))
- Starts with the UTF-8 byte order mark "\uFEFF" so spreadsheets read non-English characters correctly.
- Header: Date,Email,Phone,Form,Source,Consent
- One row per contact, newest first, lines separated by "\r\n".
  Date: created_at as an ISO 8601 UTC string. Email and Phone: the value or an empty cell. Form: form_title. Source: the display label ("Direct" for ""). Consent: consent_text.
- Quoting: wrap a cell in double quotes when it contains a comma, a double quote, a carriage return or a line feed; double any inner double quotes.
- Spreadsheet formula protection: if a cell (after trimming) starts with =, +, -, @, a tab or a carriage return, prefix it with a single quote (') BEFORE quoting. EXCEPTION: a Phone cell that matches /^\+?[0-9]+$/ is written as is (validated phone numbers may start with +).
- Put at least six examples as comments at the top of the file (a normal row, a comma, a quote, a line break, a leading "=", a phone starting with "+").
- Rows never include user_id, link_id or any other identifier.

14. ERROR, LOADING AND EDGE STATES
=====================================================================
- Unlock: the link was removed, hidden, scheduled out or its owner downgraded while the dialog was open: the database answers "unavailable" and the dialog shows "This link isn't available." If the owner changes the password, a visitor who already unlocked keeps the revealed address until the page is reloaded (in memory only); this is expected.
- Rate limits: "locked" and "rate_limited" show the messages above and never reveal timing details.
- Offline or failing network: unlock and submit keep the typed values (never auto-clear on failure), show the network message and allow retry. Only success clears the fields.
- Duplicate sign-ups look like success.
- The signup block with an unknown or invalid configuration is skipped by the mapper instead of breaking the page.
- Contacts list: a page number beyond the last page resets to the last page; deleted forms keep their contacts with the saved form title; very long values truncate with an ellipsis.
- CSV export of an empty list is prevented (the button is disabled).
- Downgraded accounts: see Section 4.
- A protected link whose url is null is never rendered as an anchor, even if the page data is malformed.
- Never show raw error text, status codes, table or function names to anyone.

21. COMMON FAILURE MODES (SELF-CHECK)
=====================================================================
1. Putting the protected address into the page data, the DOM or a cache before the password is correct.
2. Rendering a protected link as an anchor, or disabling the lock in previews.
3. Keeping passwords in state that persists, in query keys or cache, in logs, or in error messages.
4. Calling set_link_password from the Save button path so a failed save leaves the UI in a wrong state (it must have its own button and its own result handling).
5. Clearing typed values on failure, or leaving them after success.
6. A honeypot hidden with display:none or named "website" (autofill can fill it, silently dropping real sign-ups).
7. Letting visitors query contacts or link tables, or selecting user_id.
8. Letting a search term containing commas or parentheses alter the filter.
9. A CSV with formula injection, missing BOM, unescaped quotes, or a phone number that lost its "+".
10. Forgetting the consent checkbox, pre-checking it, or storing nothing about what the visitor agreed to (the database stores it; send consent true only after the box is ticked).
11. Showing signup forms or protected links to Free accounts in the preview as if visitors can see them without the "Not shown on your page" label.
12. Hiding the Contacts tab or its export and delete actions after a downgrade.
13. Adding scope: emails to owners, CAPTCHA, double opt-in, password recovery, legal text, billing.
